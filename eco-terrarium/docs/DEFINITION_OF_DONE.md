# 완료의 정의(Definition of Done) 운영 가이드

## 목적

작업 완료를 "코드를 작성했다"가 아니라 **요구사항이 검증 가능한 상태로 충족되었다**로 정의한다. 모든 작업은 아래 기본 게이트와 작업별 수용 기준을 함께 만족해야 완료다.

## 작업 시작 게이트

작업을 시작할 때 다음을 명확히 한다.

1. **문제와 사용자 가치**: 무엇이 누구에게 어떻게 개선되는가?
2. **범위와 비범위**: 이번 변경에 포함·제외되는 것은 무엇인가?
3. **관련 근거**: 연관된 `REQUIREMENTS.md`의 FR 항목, PRD, 버그 재현 절차, 디자인 또는 사용자 요청.
4. **작업별 DoD**: 관찰하거나 자동 검증할 수 있는 수용 기준. 모호한 "정상 동작" 대신 입력·결과·조건을 쓴다.
5. **검증 계획**: 각 DoD를 증명할 테스트, 빌드, 수동 확인, 코드 검토 방법.
6. **위험과 롤백**: 데이터 손실, 호환성, 성능, 보안, 배포 영향과 되돌릴 방법. 해당 없으면 `해당 없음`으로 기록한다.

요구사항이 불명확해 실제 사용 경험이나 범위를 크게 바꿀 선택이 필요하면, 구현 전에 결정이 필요한 지점을 사용자에게 확인한다.

## 기본 완료 게이트

다음은 모든 작업에 적용한다. 적용되지 않는 항목은 이유를 남긴다.

- [ ] 요구사항·수용 기준과 구현 범위가 일치하며, 의도하지 않은 변경이 없다.
- [ ] 각 작업별 DoD에 대해 통과/미통과와 직접 증거(테스트 결과, 재현 결과, 파일·라인, 화면 확인)를 기록했다.
- [ ] 변경한 코드가 타입 검사·정적 검사·빌드를 통과했다. 이 프로젝트의 기본 명령은 `pnpm build`다.
- [ ] 관련 자동 테스트를 추가 또는 갱신하고 통과시켰다. 현재 기본 명령은 `pnpm test`다.
- [ ] 정상 흐름과 실패·경계 조건을 검토했다.
- [ ] 기존 동작, 공개 데이터 형식, 저장 데이터와의 호환성 영향을 확인했다.
- [ ] 사용자에게 보이는 변경은 주요 흐름, 작은 화면, 키보드 접근성/상태 피드백을 확인했다.
- [ ] 문서, 테스트, 코드가 서로 모순되지 않는다.
- [ ] 변경 사항·검증 결과·알려진 제한 사항을 인수인계에 기록했다.

## 작업 유형별 추가 게이트

### 기능 또는 UI

- 관련 FR-* 식별자와 각 수용 기준을 연결한다.
- 처음 사용하는 흐름, 반복 사용, 빈 상태, 오류 상태를 확인한다.
- Canvas·애니메이션 변경은 프레임 저하나 리소스 누수를 점검한다.

### 시뮬레이션·알고리즘

- 대표 입력, 극단값, 잘못된 입력에서 결정성·유한성·불변식을 시험한다.
- 수식·상수 변경의 단위와 기대 효과를 문서화한다.
- 난수 사용 시 테스트 가능한 시드 또는 허용 오차를 정한다.

### 저장·DNA 공유·상태 형식

- 직렬화→역직렬화 왕복, 누락·손상 입력, 과거 형식 호환성을 검증한다.
- 로컬 저장소와 URL 입력의 실패가 앱 전체를 멈추지 않음을 확인한다.

### 버그 수정

- 수정 전 재현 절차와 수정 후 재현 결과를 기록한다.
- 원인을 막는 회귀 테스트를 추가한다. 불가능하면 이유와 대체 검증을 적는다.

### 문서·설정

- 링크, 파일 경로, 명령어, 예시를 실제로 확인한다.
- 설정 변경은 깨질 수 있는 개발·빌드·배포 흐름을 실행해 검증한다.

## 완료 판정과 증거 기준

모든 DoD 항목은 아래 중 하나로 판정한다.

| 판정 | 의미 | 완료 처리 |
| --- | --- | --- |
| 통과 | 사전에 정한 검증이 성공했고 증거가 있다 | 가능 |
| 미통과 | 검증이 실패했거나 수용 기준을 충족하지 못했다 | 불가 |
| 보류 | 환경 제약 등으로 검증하지 못했다 | 불가; 이유·영향·후속 조치를 기록 |
| 해당 없음 | 범위상 적용되지 않으며 이유가 있다 | 가능 |

테스트가 녹색이어도 해당 테스트가 수용 기준을 다루지 않으면 충분한 증거가 아니다. 반대로 수동 확인만으로 충분하지 않은 위험은 자동화된 회귀 검증을 추가한다. 모든 항목이 `통과` 또는 근거 있는 `해당 없음`일 때만 완료를 선언한다.

## 인수인계 형식

최종 결과에는 최소한 아래를 전달한다.

1. 변경 요약과 영향 범위
2. DoD 항목별 판정 및 증거
3. 실행한 검증 명령과 결과
4. 미실행 검증, 알려진 제한 사항, 후속 작업

새 작업은 `docs/TASK_TEMPLATE.md`를 복사해 이 기록을 남기거나, 동등한 구조로 이슈·PR·작업 응답에 작성한다.
