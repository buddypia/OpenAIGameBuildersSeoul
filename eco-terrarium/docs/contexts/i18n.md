# `i18n` SPEC

최종 확인: 2026-08-30 · 공개 입구: `src/features/i18n/index.ts`

## 1. 책임

플레이어에게 보이는 모든 문구를 한 곳에 모아 한국어·영어·일본어로 제공하고, 선택한 언어를 기억한다.

**소유한다**: 언어 카탈로그, 언어 감지·선택·저장, `<html lang>` 갱신, 종·퀘스트 문구의 조회.
**소유하지 않는다**: 어떤 문구를 보여줄지의 판단. 도메인이 안정적인 id를 돌려주면 이 컨텍스트가 문구를 붙인다.

## 2. 소유 요구사항

| ID | 요구 | 구현 위치 |
| --- | --- | --- |
| NFR-UX-02 | 한국어·영어·일본어 3개 언어 지원 | `domain/messages.ts`(ko), `messages.en.ts`, `messages.ja.ts`, `domain/locale.ts`, `infrastructure/localePreference.ts` |

## 3. 공개 계약

| 축 | 주요 export | 용도 |
| --- | --- | --- |
| 로케일 | `LOCALES`, `DEFAULT_LOCALE`, `LOCALE_NAMES`, `LOCALE_SHORT_NAMES`, `LOCALE_HTML_LANG`, `isLocale`, `matchLocale`, `Locale` | 언어 어휘 |
| 카탈로그 | `MESSAGES`, `Messages`, `getSpeciesText`, `SpeciesText`, `getQuestText`, `QuestText` | 문구 조회 |
| 저장 | `readStoredLocale`, `writeStoredLocale`, `resolveInitialLocale`, `getDefaultLocaleStorage`, `LOCALE_STORAGE_KEY`, `LocaleStorage` | 선택 언어 기억 |
| UI | `I18nProvider`, `useI18n`, `I18nValue`, `LanguageToggle` | React 연결 |

## 4. 규칙과 불변 조건

- **카탈로그 스키마는 한국어 트리(`messages.ts`)에서 파생된다.** 다른 언어에 키가 빠지거나 틀리면 화면에 `undefined`가 나오는 대신 **TypeScript 빌드가 실패한다.** 이것이 이 컨텍스트의 핵심 안전장치다.
- **컴포넌트에 플레이어용 문구를 직접 쓰지 않는다.** `architecture.test.ts`가 이를 강제한다.
- **도메인은 문구 대신 안정적인 id를 돌려준다.** 예: `EcosystemAdviceId`, `EnvironmentReadingId`.
- **언어를 바꾸면 `<html lang>`이 함께 갱신된다.**
- **저장소를 쓸 수 없어도 기본 언어로 동작한다.**
- **문구가 길어져도 레이아웃이 깨지지 않는다.**

## 5. 의존 방향

- **어느 컨텍스트에도 의존하지 않는다.** 반대로 각 컨텍스트의 `presentation`이 이 컨텍스트의 공개 API를 소비한다. 이 방향을 뒤집지 않는다.

## 6. 검증

| 테스트 파일 | 지키는 성질 |
| --- | --- |
| `src/test/architecture.test.ts` | 모든 언어 카탈로그가 완전하고 출하 순서를 지킴, 컴포넌트에 플레이어용 한국어 문구가 없음 |
| `src/test/ecosystemGuidance.test.ts` | 모든 안내 id가 3개 언어에 존재함 |
| `npx tsc --noEmit` / `pnpm build` | 카탈로그 키 누락을 컴파일 단계에서 차단 |

수동 확인: 3개 언어를 전환하며 주요 화면·모달에서 잘림·깨짐이 없는지, `<html lang>`이 바뀌는지.

## 7. 변경 시 주의

- 새 문구는 **세 언어 모두에** 추가한다. 하나만 추가하면 빌드가 실패한다(의도된 동작).
- 새 컨텍스트나 새 도메인 id를 만들면 대응 문구를 함께 추가한다.
- 언어를 추가하려면 `LOCALES`, `LOCALE_NAMES`, `LOCALE_SHORT_NAMES`, `LOCALE_HTML_LANG`, 새 카탈로그 파일, `architecture.test.ts`의 기대 목록을 함께 갱신한다.
