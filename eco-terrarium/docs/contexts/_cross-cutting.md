# 횡단 관심사 SPEC

최종 확인: 2026-08-30

컨텍스트 하나가 소유할 수 없는 요구사항을 모은다. **여기에 항목을 추가하기 전에 특정 컨텍스트가 소유할 수 있는지 먼저 검토한다.** 이 문서가 비대해지면 경계 설계가 흐려졌다는 신호다.

## 소유 요구사항

| ID | 요구 | 실질적 소유 위치 |
| --- | --- | --- |
| NFR-PERF-03 | 320px 모바일부터 4K까지 반응형 스케일링 | `src/app/App.tsx`의 레이아웃 + 각 컨텍스트의 `presentation` |
| NFR-PERF-04 | 번들 최소화, 외부 대용량 에셋 없는 오프라인 단일 로딩 | `vite.config.ts`, `package.json` 의존성, 절차적 생성 방침 |
| NFR-UX-03 | 명도 대비 및 색상 외 형태·아이콘 기반 상태 구분 | `DESIGN.md` 토큰, `src/index.css`, 각 `presentation` |

## 규칙과 불변 조건

- **에셋을 늘리지 않는다.** 시각·청각 자산은 SVG·Canvas·Web Audio로 절차적으로 만든다. 외부 대용량 에셋을 추가하는 변경은 NFR-PERF-04를 깨는 변경이다.
- **상태를 색만으로 구분하지 않는다.** 위험·경고·정상은 형태나 아이콘으로도 구분되어야 한다.
- **좁은 화면에서 캔버스와 제어 패널이 모두 접근 가능해야 한다.** 사이드바가 캔버스를 덮어 조작을 막지 않는다.
- **디자인 토큰은 `DESIGN.md`가 원본이다.** 컴포넌트에 원시 색상값을 흩뿌리지 않는다.

## 검증

| 수단 | 지키는 성질 |
| --- | --- |
| `src/test/architecture.test.ts` | 현미경 흐름과 사이드바 반응형 안전장치가 UI에 남아 있음 |
| `pnpm build` | 번들 산출과 크기 확인 (NFR-PERF-04) |

수동 확인이 주된 근거다.

- 320px, 768px, 1440px, 4K 폭에서 주요 화면과 모달 전체.
- 대비 검사 도구로 본문·상태 표시의 명도 대비.
- 색을 제거한 상태(그레이스케일)에서 위험·경고·정상이 구분되는지.
- 네트워크를 끊은 상태에서 새로고침해 단일 로딩이 성립하는지.

## 변경 시 주의

- 반응형이나 접근성을 이유로 도메인 규칙을 바꾸지 않는다. 표시 문제는 `presentation`에서 푼다.
- 새 의존성을 추가할 때 번들 증가분을 `pnpm build` 출력으로 확인하고 작업 기록에 남긴다.
