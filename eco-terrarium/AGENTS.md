# 작업 운영 규칙

이 저장소의 모든 변경 작업은 `docs/DEFINITION_OF_DONE.md`를 따라야 한다. 이 파일은 새 작업을 시작하는 사람과 에이전트 모두에게 적용되는 필수 게이트다.

## 필수 흐름

1. 작업 전 `REQUIREMENTS.md`, `PRD.md`, 관련 코드와 `docs/TASK_TEMPLATE.md`를 확인한다.
2. 작업별로 범위, 비범위, 위험, 검증 가능한 완료의 정의(DoD), 검증 방법을 작성한다. 작은 변경은 응답이나 이슈에 같은 항목을 간결하게 기록해도 된다.
3. 구현 중에는 요구사항과 DoD를 갱신하고, 범위 밖 변경 및 기존 사용자 변경을 피한다.
4. 완료를 주장하기 전에 DoD 항목별 증거를 확인한다. 관련 테스트·타입 검사·빌드는 가능한 한 실행하고, 실행하지 못한 검증은 이유와 잔여 위험을 명시한다.
5. 최종 보고에는 변경 내용, DoD 판정(통과/미통과), 실행한 검증 명령과 결과, 남은 제한 사항을 포함한다. 증거가 없는 항목은 완료로 표시하지 않는다.

## 품질 원칙

- 구현 방식보다 사용자 요구사항과 수용 기준을 우선한다.
- 요구사항 식별자(FR-*)가 관련되면 각 식별자를 DoD에 연결한다.
- 동작 변경에는 정상 흐름과 실패·경계 조건을 함께 검증한다.
- UI 변경은 접근성, 반응형 동작, 주요 사용자 흐름의 수동 확인 방법을 DoD에 포함한다.
- 데이터 형식·저장·공유·상태 변경은 호환성, 오류 입력, 회귀 영향을 확인한다.
- 문서만 바꾸는 작업도 링크, 명령어, 예시의 정확성을 검증한다.

재사용 가능한 작성 양식은 `docs/TASK_TEMPLATE.md`에 있다.
